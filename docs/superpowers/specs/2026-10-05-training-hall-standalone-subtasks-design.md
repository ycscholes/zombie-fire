# 历练大厅四项任务独立命令设计

## 目标

给寰球救援、终末危机、战场争霸、元素试炼各增加一个可单独运行的 CLI 子命令。四个命令都从已经打开的历练大厅任务列表页开始，并在完成后返回该列表页。

## 命令和路线

命令沿用现有 `base-training-hall-deep-abyss` 与 `base-training-hall-shop` 的命名方式：

| 命令 | 路线 |
| --- | --- |
| `base-training-hall-global-rescue` | 挑战寰球救援，领取明确的免费奖励，关闭奖励弹窗，返回历练大厅列表。 |
| `base-training-hall-terminal-crisis` | 将历练大厅列表滚动到底部，进入终末危机，执行现有免费扫荡与确认，关闭奖励弹窗，等待现有 0.5 秒业务间隔，返回列表。 |
| `base-training-hall-battlefield-contest` | 进入战场争霸，选择左下角城堡并挑战，将挑战弹窗滚动到底部，执行最后一行扫荡并逐次关闭奖励弹窗，关闭挑战弹窗后返回列表。 `--battle-times` 默认 5，且至少为 1。 |
| `base-training-hall-element-trial` | 进入元素试炼和核心试炼，领取挂机免费奖励并关闭弹窗，执行现有一次十连扫荡，关闭奖励和核心试炼弹窗，逐层返回历练大厅列表。 |

所有点击、拖动和等待继续使用现有校验、坐标、输入日志及动作封装。保留既有业务等待值和拖动后的等待，不增加自动补充次数、购买、看广告或其它未明确免费的操作。

## 结构

在 `scripts/zombie_tasks/base.py` 中将四条路线各自提取为可复用的内部任务函数。总流程 `command_base_training_hall()` 调用这些函数，四个新命令则从历练大厅列表页调用对应函数。这样既保持总流程现有顺序和操作内容，也避免总流程与独立命令的路线逐渐分叉。

在 `scripts/zombie_click.py` 注册四个命令，并接入既有任务包装与依赖同步机制。战场争霸独立命令提供与总流程一致的 `--battle-times` 默认值 5、最小值 1、后端选项和 `--dry-run`；另外三个命令提供后端选项和 `--dry-run`。更新 `scripts/README.md` 和 `SKILL.md` 的命令清单及起始页面说明。

## 错误处理与范围

复用现有窗口预检、点击/拖动失败处理和操作日志；点击失败时不猜测后续页面状态。每条新命令支持 `--dry-run`，只输出计划坐标，不发送点击或拖动。不启动游戏或执行实时领奖；本次实现按用户的功能请求修改代码，不增加或运行测试。任何静态检查或命令验证需在另行要求后进行，且不代表游戏内奖励已领取。
