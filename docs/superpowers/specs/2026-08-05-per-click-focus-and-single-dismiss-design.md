# 每次点击聚焦与单次关闭设计

## 目标

修复 `daily-rewards` 初始点击偶发失败，并让所有真实点击在投递前重新聚焦、核验准确的“向僵尸开炮”窗口。奖励弹窗关闭从双击改为单击，保留原第二次点击作为注释以便回退和校准。

## 根因与范围

`daily-rewards` 是跨巡逻、日历、福利、邮件、军团的长流程。启动阶段虽然会聚焦窗口，但每个阶段之间可能出现弹窗、广告返回或系统焦点变化。固定坐标点击必须以点击时刻的前台目标窗口为准，不能依赖流程开始时的焦点状态。现有 `perform_click()` 已接近这个边界；本次把它明确为唯一入口并以测试锁定顺序。

本次不改变坐标、奖励路线、重试次数、等待时长或非操作命令的免聚焦规则。

## 设计

`perform_click()` 在每次实际投递前按固定顺序执行：

1. 聚焦标题包含“向僵尸开炮”的已校准窗口；
2. 核验窗口仍为同一位置与尺寸；
3. 使用指定后端投递一次点击。

若投递失败，现有的一次重试仍会重复上述完整顺序。测试须覆盖首个点击和重试点击都先聚焦、再核验、最后投递。

将 `dismiss_reward_twice()` 收敛为单次 dismiss（并相应改名以反映行为）。第二次 `perform_click()` 与其日志保留为相邻的中文注释；只保留一次正常的 post-click 等待，不再额外等待后点击相同坐标。

为窗口聚焦、窗口一致性检查、点击投递、单次关闭及旧双击保留代码补充简洁中文注释。所有注释解释安全性或时序原因，不翻译显而易见的语法。

## 验收与测试

- 单元测试证明每次真实点击均为“聚焦、核验、投递”顺序；失败重试亦如此。
- 单元测试证明奖励 dismiss 仅调用一次点击、没有旧的二次等待；源文件保留已注释的旧第二次点击。
- 运行全部 `test_zombie_click.py`、`py_compile`、技能快速校验、模拟 `daily-rewards --dry-run` 和 `git diff --check`。
- 不用模拟干跑证明真实窗口聚焦；它仅验证坐标和流程调度。
