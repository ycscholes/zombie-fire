# 奖励领取后最小间隔设计

## 目标

对项目内所有实际触发奖励领取结果的点击，保证从该点击完成到下一次物理输入（点击或拖拽）之间严格大于 1 秒。规则在共享输入层定义并由各业务流程通过语义化入口调用，避免逐模块复制等待逻辑。

## 范围

奖励领取包括免费资源领取、一键领取、扫荡确认、奖励行领取及等价的领取结果动作。奖励弹窗关闭、页面导航、标签切换和拖拽不属于奖励领取动作；它们仍沿用各自的基础节流或业务等待。

广告播放等待、页面加载等待等业务等待保持现状。它们可以比本规则更长，但不能抵消领取动作本身的最小间隔。

## 设计

在 `scripts/zombie_common.py` 定义项目级常量 `REWARD_POST_ACTION_MIN_SECONDS = 1.05`。选择 1.05 秒而非 1.0 秒，避免系统调度和日志精度使“至少 1 秒”落在边界上。

新增共享 `perform_reward_click()`：使用与普通点击相同的窗口校验、输入审计、投递和日志格式，但在成功投递后执行不少于该常量的等待。业务模块以此入口替换奖励领取动作；非领取动作继续使用 `perform_click()` 或 `perform_dismiss_click()`。

奖励点击的操作日志增加 `post_reward_wait_ms`，以毫秒记录实际强制等待目标，使运行日志可直接验证规则。现有日志时间戳保持不变，不以秒级显示的 `0 秒`作为是否遵守规则的判据。

## 错误处理

点击投递失败时不等待，并维持既有的一次重试及阶段恢复策略。只有成功领取点击才添加等待。等待期间不改变窗口校验策略；下一次输入仍执行共享预检。

## 验证

1. 单元测试验证 `perform_reward_click()` 在成功投递后调用至少 1.05 秒等待，并写入等待字段。
2. 单元测试验证普通点击与奖励弹窗关闭不被该规则误改。
3. 流程测试验证典型领取路径（巡逻、旅程、商城、军团）调用奖励入口。
4. 运行全量 Python 测试套件；真实运行日志中，领取点击到后续物理输入的毫秒级间隔必须大于 1000ms。
